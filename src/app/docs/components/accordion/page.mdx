# Accordion

Expandable stacks built on native `details`/`summary` — disclosure
semantics, keyboard toggling and state persistence come from the
platform, not from script. Each item toggles independently, so several
can be open at once; pass `open` on an item to start it expanded.

```tsx

        </AccordionContent>
      </AccordionItem>
      <AccordionItem>
        <AccordionTrigger>Can several be open at once?</AccordionTrigger>
        <AccordionContent>
          By default every item toggles independently; reach for

        </AccordionContent>
```

## Examples

### Control panel

The content region is an ordinary `div`, so anything can live there —
below, a settings sheet with working `Checkbox` wells.

## API reference

### Accordion

The beveled container stack. No props of its own beyond a `div`'s —
the shared composition contract applies.

### AccordionItem

One panel, rendered as a native `details` element — every `details`
prop passes through.

| Prop | Type | Default | Description                    |
| ---- | ---- | ------- | ------------------------------ |
| `open` | boolean | —     | Starts the item expanded. Afterwards the browser owns it — matching `details` behavior, not a React-controlled prop. |

### AccordionTrigger

The row that toggles the item — a `summary` with the webkit marker
hidden and a folder-arrow glyph that snaps 90° open via the
`group-open` state. No props of its own beyond a `summary`'s.

### AccordionContent

The revealed region — a padded `div` rendered only while the item is
open. No props of its own.
