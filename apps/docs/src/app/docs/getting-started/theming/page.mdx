# Theming

Every color in the library comes from a semantic token, so theming is a
matter of the token values — never of the components. There is one
whole set of values for light (`:root`) and one for dark (`.dark`), and
the components read whichever is active.

## Three layers

The tokens are stacked, and each layer has one job:

| Layer | What it holds | Who edits it |
| --- | --- | --- |
| the scale | a ramp per color family — `--accent-1` … `--accent-13` | you, to re-brand a family |
| the names | the roles the components ask for — `--accent`, `--surface` | you, per theme |
| the mapping | `@theme inline`, turning each name into a Tailwind color | once, on install |

The names are indirections through the scale. The light theme's accent
is a step of the teal ramp, and so is the dark theme's — the light one
takes the deep end, the dark one the bright end:

```css
:root {
  --accent-1: #d7f5ef;   /* the ramp: pale at 1, deep at 13 */
  --accent-8: #0f766e;   /* the deep end */
  --accent-9: #0b5d57;

  --accent: var(--accent-8);        /* the name the components ask for */
  --accent-strong: var(--accent-9);
  --accent-soft: var(--accent-2);
}

.dark {
  --accent: var(--accent-5);        /* the same ramp, the bright end */
  --accent-strong: var(--accent-4);
  --accent-soft: var(--accent-11);
}
```

Because the ramp is fixed across themes, "the accent" means the same
color in both — and re-branding the family is a change to the ramp,
which both themes follow.

The neutral tokens — `--surface`, `--ink`, `--bevel-light` — have no
ramp: they are surfaces and edges, and their names already say what
they are.

## The values

```css
:root {
  --surface: #f4f2ea;
  --ink: #171a20;
  --bevel-light: #ffffff;
  --bevel-dark: #171a20;
  /* …one matching value per theme for every token */
}

.dark {
  --surface: #191d23;
  --ink: #e6e8ec;
  --bevel-light: #383f4a;
  --bevel-dark: #0a0c10;
  /* … */
}
```

Note what shifts between themes: not just colors but *depth edges* —
dark mode lightens `--bevel-light` (the raised edge) and darkens
`--bevel-dark`, so bevels still read as bevels on dark surfaces.

## The switch

The persisted-or-system choice is applied before first paint to avoid a
flash, then toggled at run time by flipping the `dark` class:

```html
<script>
  (function () {
    try {
      var t = localStorage.getItem("retro-theme");
      var d = t
        ? t === "dark"
        : window.matchMedia("(prefers-color-scheme: dark)").matches;
      document.documentElement.classList.toggle("dark", d);
    } catch (e) {}
  })();
</script>
```

The playground's ThemeToggle persists the choice under the
`retro-theme` localStorage key and reflects the live class state.
Anything that reads `document.documentElement.classList` can join.

## Adding a color family

New families follow the token grammar: a ramp, then a base plus
`-strong`, `-ink` and `-soft` pointing into it, declared in *both*
themes, and mapped once so Tailwind utilities exist:

```css
:root {
  /* the ramp */
  --success-1: #ddf3e1;
  --success-6: #15803d;
  --success-7: #166534;

  /* the names */
  --success: var(--success-6);
  --success-strong: var(--success-7);
  --success-ink: #eafff1;
  --success-soft: var(--success-1);
}

.dark {
  --success: var(--success-3);
  --success-strong: var(--success-2);
  --success-ink: var(--success-10);
  --success-soft: var(--success-9);
}

@theme inline {
  --color-success: var(--success);
  --color-success-strong: var(--success-strong);
  /* … */
}
```

After that, `bg-success-soft`, `text-success-strong` and friends are
ordinary utilities, and a variant like the Toast's `success` shows up
across both themes.

## Customizing

Any single token can be overridden in your own global stylesheet —
either per theme or conditionally, e.g. a brand accent:

```css
:root {
  --accent: #a5cf02; /* acid green, the incline brand way */
}
```

Or re-brand the whole family by moving the ramp — one change, both
themes follow:

```css
:root {
  --accent-8: #4d7c0f; /* the step the light theme's accent reads */
  --accent-5: #84cc16; /* and the one the dark theme reads */
}
```

The library's rules sit in a `retro-ui` cascade layer below Tailwind's,
so your overrides win whether they come before or after the import —
see [Styling](/docs/getting-started/styling).

Two cautions:

- **Check contrast in both themes.** The tokens are named by role, so
  a new value answers to many components at once — read text on its
  intended surface, not against the perfect swatch.
- **Textures never carry meaning.** `bg-hatch` and `bg-dither` are low
  contrast by design; state must always come from token color or
  depth, and the texture is decoration on top.
