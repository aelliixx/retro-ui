# Installation

```sh
npm install @retroui/ui
```

`react`, `react-dom` and `tailwindcss` (v4) are peer dependencies. The
library brings `clsx`, `tailwind-merge` and `class-variance-authority`
with it.

## 1. Import the stylesheet

The library ships its CSS as a stylesheet, meant to be imported into your
global CSS — **before** Tailwind:

```css
/* app/globals.css */
@import "@retroui/ui/styles.css";
@import "tailwindcss";
```

Two things in that stylesheet travel together, and both are needed:

- the CSS variables in `:root` / `.dark` (the colour values, one set per
  theme) and the `@theme inline` block that maps each one into a Tailwind
  colour, so `text-ink`, `bg-surface-2` and friends exist;
- the cascade layer order. The library's own rules sit in a `retro-ui`
  layer below Tailwind's, so your utilities and your plain CSS always
  win — no `!important`, no import order to remember. The statement
  only counts if it comes first, which is why the library goes first.

The order is the whole reason the two imports are not interchangeable:
swap them and the layer statement arrives too late to matter.

If you would rather take the two halves separately, they are published
on their own — `@retroui/ui/tokens.css` (the variables and the Tailwind
mapping) and `@retroui/ui/utilities.css` (the component skin: the
etched focus ring, the era's textures, the styled slider, the
placeholder shell).

## 2. Render something

```tsx
import { Button, Field, Input } from "@retroui/ui";

export function Ready() {
  return (
    <Field label="Save name">
      <Input defaultValue="untitled.txt" />
      <Button variant="primary">Save</Button>
    </Field>
  );
}
```

Every component takes a `className` and composes it with
`tailwind-merge`, so your class always wins over the library's.

## 3. Set the theme

The dark theme is a class on `<html>`, not a media query — you own the
switch:

```tsx
document.documentElement.classList.toggle("dark");
```

Re-brand by overriding the variables; the components follow. See
[Theming](/docs/getting-started/theming) for the full list and
[Styling](/docs/getting-started/styling) for how the layers fit
together.

## 4. Optional — the type stack

The playground uses Geist Sans (body), Geist Mono (`font-mono`) and
Silkscreen (`font-pixel`, the pixel wordmarks). Any fonts will work —
the components reference `font-mono` and `font-pixel` by name, so
redefine them in `@theme` if you ship different faces.

```tsx
import { Geist, Geist_Mono, Silkscreen } from "next/font/google";

const geistSans = Geist({ variable: "--font-geist-sans", subsets: ["latin"] });
const geistMono = Geist_Mono({ variable: "--font-geist-mono", subsets: ["latin"] });
const silkscreen = Silkscreen({ variable: "--font-silkscreen", subsets: ["latin"], weight: ["400", "700"] });
```

## Copy the source instead

The library is also distributed as source, for the era way — like
checking the source off a floppy. Copy the component files and the
`cn()` helper out of the repository into your own project and tailor
them in place. The files use relative imports and no path aliases, so
they work wherever you drop them:

```sh
src/
├── components/
│   └── ui/            # 32 components + barrel
│       └── …
├── lib/
│   └── utils.ts       # cn() with tailwind-merge extensions
└── styles/
    ├── tokens.css     # the theming contract
    └── utilities.css  # the component skin
```

Keep the barrel `src/components/ui/index.ts` and the imports read like
the docs.

The docs you are reading right now are themselves built from the
library — the sidebar tree, the drawer and the code wells are
`ScrollArea`, `Dialog`, `Collapsible` and `Card` in working order.
