# Collapsible

The keep — a trigger that expands one panel, instantly. Reach for it
instead of `Accordion` when there is a single panel and the trigger
shouldn't look like a folder row: both parts are bare, styled by you,
and wired together for free.

Real `button` semantics throughout: `aria-expanded` + `aria-controls`,
click/Space/Enter. The panel stays mounted while closed but `hidden`,
so form state inside survives toggling. Style on the `data-state`
attribute (`open`/`closed`) of every part — that is how the demos flip
their chevron.

## Demo

<MinimalCollapsible />

```tsx
import {
  Collapsible,
  CollapsibleContent,
  CollapsibleTrigger,
} from "@retro-ui/ui";

export function MinimalCollapsible() {
  return (
    <Collapsible className="group">
      <CollapsibleTrigger>
        <span
          aria-hidden="true"
          className="inline-block transition-none group-data-[state=open]:rotate-90"
        >
          ▸
        </span>
        Advanced sharing
      </CollapsibleTrigger>
      <CollapsibleContent className="mt-2">
        <p className="border-l-2 border-border-muted pl-3 text-sm text-ink-muted">
          The panel stays mounted but hidden while closed — anything
          inside survives the flip, instantly, no animation.
        </p>
      </CollapsibleContent>
    </Collapsible>
  );
}
```

## Examples

### Controlled + kept state

The controlled form (`open` + `onOpenChange`) makes the outside world a
panel authority; the `Input` below keeps its typed contents across
collapses because the content stays mounted.

<ControlledCollapsible />

```tsx
"use client";

import { useState } from "react";

import {
  Button,
  Collapsible,
  CollapsibleContent,
  CollapsibleTrigger,
  Input,
} from "@retro-ui/ui";

export function ControlledCollapsible() {
  const [open, setOpen] = useState(true);
  return (
    <Collapsible open={open} onOpenChange={setOpen}>
      <div className="flex flex-wrap items-center gap-3">
        <CollapsibleTrigger>
          <span
            aria-hidden="true"
            className="inline-block transition-none group-data-[state=open]:rotate-90"
          >
            ▸
          </span>
          Preferences
        </CollapsibleTrigger>
        <Button size="sm" variant="outline" onClick={() => setOpen(!open)}>
          {open ? "Collapse" : "Expand"}
        </Button>
        <span className="font-mono text-sm">
          state = {open ? "open" : "closed"}
        </span>
      </div>
      <CollapsibleContent className="mt-2">
        <Input
          defaultValue="typed here — survives collapsing"
          className="max-w-xs"
        />
      </CollapsibleContent>
    </Collapsible>
  );
}
```

## API reference

### Collapsible

Groups the parts and owns the open state.

| Prop          | Type                         | Default | Description |
| ------------- | ---------------------------- | ------- | ----------- |
| open          | boolean                      | —       | Controlled open-state. |
| defaultOpen   | boolean                      | false   | Uncontrolled initial open-state. |
| onOpenChange  | (open: boolean) => void      | —       | Fires with the next open-state — controlled and uncontrolled. |

### CollapsibleTrigger

The toggling `button` — styled like a standard surface key and
overwrite any way you like via `className`. Carries `aria-expanded` and
`data-state` (`open`/`closed`). A click that is `defaultPrevented`
inside your handler suppresses the flip.

### CollapsibleContent

The panel — stays mounted but `hidden` while closed. Carries
`data-state` and `aria-labelledby` pointing back at the trigger.
